# Closeout and capability harvest

Every project produces two deliverables:

1. the artifact or outcome the project was commissioned to produce; and
2. the capability the Navy Yard has gained because the project happened.

## Closeout questions

- What was delivered, deployed, accepted, or intentionally stopped?
- Which claims were supported, weakened, or left unresolved?
- Which evaluator and harness results matter?
- What routing decision worked or failed, and why?
- What context was essential, missing, or unnecessary?
- Which model, agent, workbench, or workflow performed well under what
  conditions?
- What should be repaired, versioned, taught, or retired?
- Where should the learning live in Notion, ATS, Fleet, the skill package, or
  a new improvement work item?

## Harvest destinations

| Learning | Durable destination |
|---|---|
| Project commitment and final state | Linear |
| Design rationale, precedent, client context, lesson | Notion |
| Executable follow-up and dependency | Beads, linked to Linear |
| Routing behavior or integration change | Hermes/Harbormaster package |
| Skill/workbench improvement | Skill or workbench version backlog |
| Capability comparison or regression | ATS |
| Capacity or reliability observation | Fleet |
| Human-facing synthesis | Navy Yard Chart or Lighthouse workflow |

Closeout is not complete until the artifact state and capability state are
both recorded.
