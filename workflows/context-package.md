# Assemble a context package

## Inputs

- `WorkItem` and related Linear records;
- Notion design, memory, precedent, and client/project records;
- Beads dependencies and discovered work;
- selected workbench requirements;
- Fleet and ATS information;
- policy and boundary records.

## Procedure

1. Start from authoritative sources.
2. Preserve the original request and intended use.
3. Add scope, acceptance criteria, and out-of-scope limits.
4. Attach the design record if required.
5. Load only relevant project memory, standards, examples, and tools.
6. Add evaluator and deployment requirements.
7. Add Bosun, dependency, budget, handoff, and escalation information.
8. List missing, conflicting, or deliberately omitted context.
9. Assign a completeness level.
10. Record a stable package identifier and provenance.

The package is ready for execution only when the receiving bench could act
without inventing requirements.
